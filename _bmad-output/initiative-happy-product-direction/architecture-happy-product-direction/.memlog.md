- (constraint) Every new user begins with a Supabase anonymous auth user; there is no separate guest-data mode. Later sign-up or login must link the provider identity to the existing anonymous auth user so course progress, practices, journal entries, and insights remain attached to the same user id.
- (constraint) Durable product data is scoped to the authenticated Supabase user id and protected by user-level access rules; client Redux and React Query state are caches and coordination surfaces, not independent ownership of durable records.
- (decision) Insights are gated by sufficient trustworthy user data. The product must show an insufficient-data state until the configured threshold is met, then present a time-bounded, explainable, non-diagnostic insight from the canonical data sources.
- (decision) Insight readiness uses a staged ladder: immediate post-practice feedback describes only the current session; an activity summary becomes available after 3 completed relevant practices in a rolling 7-day window; a pattern insight becomes available after at least 5 relevant structured observations across at least 3 distinct days in a rolling 30-day window.
- (decision) The first pattern insight is deterministic and source-transparent. It uses structured practice/reflection fields, shows the observation count and time window, uses emerging-pattern language, and does not infer diagnosis, causality, or treatment.
- (decision) Free-text AI narrative is deferred from the first insight contract. It may be added only after privacy, processing, consent, redaction, and safety behavior are verified; it cannot be required for core insight availability.
- (decision) Insight readiness is per anonymous-or-identified Supabase user id. No cross-user aggregation or population comparison is part of the first product-direction architecture.
- (decision) Adopt a domain-oriented layered architecture with client orchestration: presentation routes and domain UI compose flows; domain services own use cases and contracts; Supabase tables/RLS and Edge Functions own durable or privileged work. Do not introduce a second central workflow backend for this initiative.
- (decision) Journey owns StarterPath selection, course enrollment, active-course state, and course/node progress. Practice owns exercise response and completion. Journal owns private reflection records. Insights are read-only projections over canonical practice/reflection records and never write back into those domains.
- (decision) Use stable domain identifiers and explicit contracts for the first loop: goal_id -> lesson/node_id -> practice_id -> reflection_prompt_id -> next_action. Do not infer cross-domain routing from display labels, translated text, or screen paths.
- (decision) Durable mutations use one domain-owned mutation path, include the authenticated Supabase user id through the auth boundary, return an explicit saved/completed result, and invalidate or refresh client caches. Redux and React Query may optimistically render but cannot become a second durable source of truth.
- (decision) Anonymous Supabase users and identified users share the same user-id ownership model. Account claiming links a provider identity to the current anonymous user; an identity conflict must stop and offer an explicit existing-account recovery path rather than silently merging or replacing data.
- (decision) Insight readiness is an explicit per-insight contract with insufficient-data, activity-summary, and pattern-ready states. Pattern-ready requires 5 relevant structured observations across 3 distinct days in a rolling 30-day window; the output states its window and observation count.
- (decision) The first pattern insight uses deterministic structured fields and transparent wording. Free-text AI narratives are optional deferred work and cannot be required for core insight availability.
- (decision) Sensitive reflection content is private by default, scoped by auth.uid(), excluded from analytics payloads and ordinary logs, and not sent to AI or third-party processing without a verified product policy and user-facing explanation.
- (decision) A saved state is shown only after the durable write is acknowledged. In-progress drafts may be local and marked unsynced, but unsynced content cannot feed insights or be represented as completed practice/reflection.
- (direction) The first initiative tracer is goal -> lesson -> practice -> text reflection -> deterministic time-bounded insight. Voice, photo, broad AI narratives, cross-user comparisons, diagnosis, and treatment recommendations remain deferred.
- (assumption) The current brownfield stack is the binding seed: Expo 56, React Native 0.85, Expo Router 56, Redux Toolkit 2, TanStack Query 5, Supabase JS 2, and TypeScript 6. Existing code owns exact dependency details; this spine does not add dependencies.
- (question) The product must later verify the hosted behavior and policy for anonymous identity linking, AI processing, retention, deletion, and high-risk content before marketing or expanding insight surfaces.
- (decision) Auth readiness is provider-owned and monotonic within a session: cold -> auth_ready -> profile_ready -> identity_ready, or recovery_required/failed. identity_ready emits only after the current Supabase user and profile row are hydrated; a normal linked result preserves the anonymous user id.
- (decision) IdentityLinkResultV1 uses the exact statuses linked, recovery_required, cancelled, retryable_failure, and failed. retryable is true only for retryable_failure; provider/session identity mismatch blocks replay and reads.
- (decision) Journey persists StarterPathProgressV1 in user_starter_path_progress keyed by user_id, path_id, and path_version, while user_preferences.active_path_id is the only active-path pointer. Serialized compare-and-swap protects path switching and completion from overwriting each other.
- (decision) PathStepCompletedV1 is the only cross-domain completion event that advances StarterPath progress. It carries path/version, step/source identity, stable practice_session_id when relevant, idempotency_key, causation_id, and schema_version; duplicate event ids or idempotency keys are no-ops.
- (decision) PracticeCompletionV1 uses a stable practice_session_id created at practice start. v5 completion evidence comes only from a qualifying submitted user_node_responses record; user_node_progress is summary state and node_attempts are not completion evidence. Standalone completion uses a stable completed exercise_entries row.
- (decision) Guided reflection requires ReflectionContextV1 lineage to its immutable path/version, practice session, practice reference, prompt, and journal record. The canonical journal record and required lineage acknowledge atomically; journal_ai and moods are optional children and cannot count as evidence before acknowledgement.
- (decision) InsightObservationV1 uses a versioned insight-family registry, family-validated metrics, deterministic identity from source_id plus insight_family, and evidence_key grammar insight_family:path_id:path_version. Schema version changes projection meaning, not observation identity.
- (decision) Insight time uses a per-user fixed IANA timezone epoch. The first structured observation pins the timezone; an explicit reset starts a new epoch without rewriting history. Windows are half-open and evaluated through the timezone library; invalid timezone input falls back to UTC and leaves pattern readiness ineligible.
- (constraint) UnsyncedOperationV1 local_user_id is always the current Supabase UUID, never a device or guest id. Replay is ordered per user and stops at the first unresolved dependency or identity mismatch.
- (constraint) Production release is blocked when an Edge Function contains a hardcoded service-role or provider credential. Secrets must be externalized and rotated when exposed; hosted migration, completion projection, lineage, readiness, and replay gates must be verified before dependent capabilities ship.
- (event) spine finalized after deterministic lint and reviewer-gate fixes; architecture adopted as a companion of the product-direction spec
