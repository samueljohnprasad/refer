# App UI localization source inventory

Snapshot: 2026-10-04, from `node scripts/validate-localization.mjs --inventory-files`. This is a candidate inventory for Tasks 3–9; it is not a claim that all app copy has been translated. The validator scans TypeScript/TSX under `app/`, `src/`, `components/`, and `hooks/` for JSX text and rendered string expressions, copy-bearing string props and config fields, and direct alert/toast arguments. Each line below is a file with the number of literal candidates and their detection contexts. Run `--inventory` for every source location.

## Namespace ownership

| Namespace | Owner |
| --- | --- |
| `common` | Shared navigation, actions, generic errors, permissions, accessibility, cross-feature achievements and rewards |
| `home` | Home, discovery, dashboard, and home-only progress copy |
| `journal` | Journal capture, entries, prompts, tracking, insights, and diary-specific labels |
| `onboarding` | First-run setup, sign-in prompts inside onboarding, and goal selection |
| `exercises` | Exercise catalog, exercise UI, bundled prompts/options/feedback, and exercise completion |
| `journeys` | Journey map, course catalog, nodes, lessons, and journey-specific progress |
| `habits` | Habit setup, check-ins, and habit-specific reminders |
| `settings` | Preferences, language, support, premium/account settings, and settings-only confirmations |

Use semantic, lower camel-case paths such as `settings:notifications.emptyTitle`. Reuse a key only when meaning and grammar match across surfaces. Keep interpolation names stable, for example `{{count}}`; use i18next plural suffixes `_one` and `_other`. Do not put response IDs, telemetry names, scoring values, or user text in translation keys. Existing hashed exercise keys may remain until their owning exercise migrates.

## Validation contract and exclusions

The validator reads all eight locale directories and compares every namespace and leaf key against `src/locales/en`, including array positions, empty containers, and primitive types. It compares unique `{{variable}}` names for each string. Missing/extra namespaces, missing/extra keys, type drift, and placeholder drift fail separately. Its source scan reports unapproved literals and exits nonzero during staged migration. The narrow exact-value allowlist is `Happy`, `Happy Premium`, `CBT`, `AI`, and `XP`; these are product names/initialisms, not a general English waiver. Inspect the location before deciding any other literal is intentional.

Explicitly outside this inventory: `app/dev/`, `app/tabs/screens/(tracking)/test-charts.tsx`, `*.test.*`, `*.spec.*`, `__tests__/`, `__mocks__/`, debug/storybook files, and the HTML document meta tags in `app/+html.tsx`. The app also must not translate Supabase schemas/migrations/seeds, database-authored course content, server/AI responses, or user-entered journal/reflection/coping-card/voice text. App-owned labels around those values remain in scope. `src/network/sample_insights_20.json` is a sample payload; `src/animations/telegram-theme-switch/assets/switch-theme.json` is an animation asset. App Store metadata and screenshots are separate.

Detection is intentionally a candidate audit: dynamic string composition, arbitrary helper arguments, native configuration outside these four directories, and copy in unrecognized property names need human review in later tasks. Some candidates may be unreachable demos or technical strings; confirm ownership before migrating them. The current i18n runtime and resource typing already declare all eight namespaces, including `journeys`, so Task 1 needs no changes to those dirty files.
