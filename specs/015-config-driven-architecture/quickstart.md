# Quickstart Validation Guide: Config-Driven Plugin Architecture

**Feature**: `specs/015-config-driven-architecture`  
**Date**: 2026-09-03

---

## Prerequisites

- Node.js + npm/bun installed.
- Expo CLI available (`npx expo`).
- iOS Simulator running (iPhone 16 or equivalent, iOS 26+).
- Dev build present or Metro running.

---

## Scenario 1: Happy path — all plugins enabled

**Purpose**: Verify system bootstraps correctly and all active plugins are initialized.

**Setup**: Ensure `config/app.config.json` has all plugin IDs with `enabled: true`.

**Steps**:
1. Start Metro: `npm run ios`
2. Open the app in the simulator.
3. Navigate to each domain's feature screen (e.g. Rewards, Course map).

**Expected outcome**: All screens load without errors. No "plugin not found" or config validation errors in the Metro console.

---

## Scenario 2: Plug-out a feature

**Purpose**: Verify that setting `enabled: false` for a plugin removes it with zero core code changes.

**Setup**: In `config/app.config.json`, set `plugins.rewards.enabled = false`.

**Steps**:
1. Restart Metro (or trigger a reload).
2. Navigate the app.

**Expected outcome**:
- The Rewards entry point (journey map chest / trophy / celebration) is absent from the UI.
- No crash or blank screen — the app renders gracefully without the plugin.
- Metro console shows a log line confirming the plugin was skipped (e.g. `[Orchestrator] Skipping plugin: rewards (disabled)`).

---

## Scenario 3: Malformed config is rejected

**Purpose**: Verify the config validator halts safely with a clear diagnostic.

**Setup**: Corrupt `config/app.config.json` — remove the `version` field.

**Steps**:
1. Reload the app.

**Expected outcome**:
- App does not reach the main screen.
- A clear error boundary or console message indicates which config field is missing.
- No silent failure or partial initialization.

---

## Scenario 4: Plugin dependency validation

**Purpose**: Verify the Orchestrator detects a missing dependency and refuses to boot.

**Setup**: In `config/app.config.json`, disable plugin `A` but leave plugin `B` (which depends on `A`) enabled.

**Steps**:
1. Reload the app.

**Expected outcome**:
- App halts or shows a clear diagnostic: `[Orchestrator] ERROR: Plugin 'B' requires 'A', which is disabled.`
- No partial initialization of plugin B.

---

## Scenario 5: No hardcoded strings in component output

**Purpose**: Verify all displayed strings come from `AppConfig.content.strings`.

**Setup**: In `config/app.config.json`, change the value of `content.strings.rewards.chestCTA` to a sentinel string `"TEST_CTA_LABEL"`.

**Steps**:
1. Reload the app and open a unit with an available chest.

**Expected outcome**: The chest CTA button shows `"TEST_CTA_LABEL"` rather than any hardcoded fallback.
